Calling an API is the easy half. The hard half is discovering a tool the agent was not hard-coded to know, holding the credential where the model cannot read it, and keeping one user's grants off another user's session. Generic integration products assumed a person would pick the app and click consent. This collection is for the layer that does that work inside an agent loop.

Some cards are one server for one system. The GitHub MCP Server, Framelink for Figma, and the MCP Toolbox for Databases are that shape. Others are registries and gateways that put many servers behind discovery or a single endpoint: Smithery, MCP Gateway, Obot, ToolHive, MCPJungle, MetaMCP, ContextForge, and MCPHub. Arcade, Composio, Nango, and Scalekit sit on tokens. Arcade's docs emphasize OAuth where secrets stay out of the model. Nango's dossier describes fetching a valid connection at runtime rather than pasting a token into the prompt. Snyk Agent Scan and Grey Ridge x402 Tools are about inspecting a server before an agent trusts it.

A local stdio server is simple to attach and means the process, and often the token, lives next to the client. A remote server moves that trust to a host and needs an authentication story. The current Model Context Protocol architecture describes stdio for local processes and Streamable HTTP for remote ones. A gateway can shrink the number of servers a client configures, and it becomes a place where every tool call can be seen or stopped. That is useful, and it is also a new operator.

If the protocol itself is unfamiliar, start with [Getting started with MCP servers](/guides/getting-started-with-mcp-servers/).
